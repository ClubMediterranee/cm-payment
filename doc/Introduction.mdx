## What it is

`@clubmed/caps` is the Club Med Payment SDK: a set of React components and providers that render the
Club Med payment form and orchestrate the checkout flow with the payment service providers (PSP)
supported by the platform.

This Storybook documents the SDK UI. It lives in a PNPM monorepo that groups the building blocks
around the payment SDK:

- `packages/sdk` — the payment SDK library published as `@clubmed/caps` (the components shown here)
- `packages/app` — demo/acceptance application (Vite, port 4003)
- `packages/server` — Ts.ED + Fastify integration server that proxies Club Med APIs and serves the built front-end

## Getting started (monorepo)

Install the workspace dependencies:

```sh
pnpm install
```

(Optional) Regenerate the types from the schemas / OpenAPI:

```sh
pnpm generate:types
```

Run the pieces you need in watch/dev mode:

```sh
pnpm dev:storybook   # Storybook — SDK UI / components (this site)
pnpm dev:sdk         # SDK in watch build mode (@clubmed/caps)
pnpm dev:app         # Demo/acceptance app (Vite, port 4003)
```

You can scope any command to a single package with `--filter`:

```sh
pnpm --filter @clubmed/caps run build
pnpm --filter @clubmed/app run dev
```

## Usage

Wrap your app with the SDK providers, then render the `PaymentWidget`. Every public component and
provider is exported from the package root:

```tsx
import { PaymentConfigProvider, QueryClientProvider, PaymentWidget } from '@clubmed/caps';

export function Checkout() {
  return (
    <QueryClientProvider>
      <PaymentConfigProvider>
        <PaymentWidget />
      </PaymentConfigProvider>
    </QueryClientProvider>
  );
}
```

The SDK also exposes the individual building blocks used to compose the form, among others:

- `PaymentWidget` — the full payment form orchestrating provider selection and submission
- `PaymentProviders` — the list/selection of available payment service providers
- `BillingAddress`, `ContactChoice`, `Cgv`, `Donation` — form sections
- `CardInstallments`, `PaymentSchedule` — installment and schedule UI
- `SubmitButton`, `FormPanel` — form primitives
- `CapsForm`, `PaymentConfigProvider`, `QueryClientProvider` — providers
- `useCapsConfigContext`, `useDisclosure` — hooks
- `formatCurrency`, `formatDate`, `fetcher` — utilities

Browse the components in the sidebar (under **SDK**) to see props, controls and interaction tests.

## Scripts (root)

```sh
pnpm lint            # ESLint (shared config)
pnpm lint:fix        # ESLint with autofix
pnpm test            # Vitest across packages (incl. Storybook interaction tests)
pnpm build           # Type-check and bundle every package
pnpm build-storybook # Static Storybook build
pnpm chromatic       # Publish stories to Chromatic
pnpm generate:types  # Regenerate types (SDK + app + server)
```

## Testing

- Vitest + React Testing Library for unit/UI specs, stored beside the component (`Component.test.tsx`).
- Storybook interaction tests live in `*.stories.tsx` files using `play` functions and run through
  `@storybook/addon-vitest` (`pnpm test`).
- Network calls in stories are mocked with MSW via `msw-storybook-addon`.
